# JWT Ticket Security

A massive problem with legacy ticketing systems is "Screenshot Sharing". A student buys one ticket, screenshots the QR code, and sends it to five friends. The first one to the gate gets in, and the others cause chaos.

UniTix solves this completely using **JWT (JSON Web Tokens)**.

## Cryptographic Signatures

When a student successfully purchases a ticket, the UniTix backend generates a payload containing:
- `ticketId`
- `eventId`
- `userId`

The backend then **signs** this payload using a highly secure, secret server key (stored in `.env.local`). This generates a long string of cryptographic text (the JWT).

This JWT string is what is converted into the large QR Code on the student's phone.

## The Validation Process

When a Scanner points their camera at the QR code at the gate:

1. The scanner reads the JWT string.
2. It sends the string to the UniTix backend API (`/api/scan`).
3. The backend uses the secret server key to **verify the signature**. 
4. If a student tries to generate a fake QR code using a free online tool, the signature will not match our secret key, and the backend instantly rejects it with a **Red Error Screen**.

## Non-Transferrable Policies

Because the ticket is tied directly to the `userId` in the payload, tickets are strictly non-transferrable. If an Event Manager needs to verify identity, the scanner interface will display the exact name and Registration Number of the student who is *supposed* to be holding that ticket.
